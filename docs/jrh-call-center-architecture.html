③ A Call, Step by Step

Follow one caller from "hello" to a fully-logged, transcribed record.

1

📞 Caller dials in & meets Zuri

The AI agent (Retell) answers, handles the intake, and when the caller asks for a person — or Zuri can't resolve it — triggers a transfer.

2

🤖 Cold transfer via SIP INVITE

Retell transfers to +1 267-508-7940. Using SIP INVITE (not REFER) keeps the media path alive so recording never drops through the handoff.

3

☎️ Twilio asks our app what to do

The inbound call hits /voice/incoming. The app returns TwiML: play the consent notice ("this call may be recorded"), then place the caller into the queue.

4

🌩️ Through the tunnel to the VPS

That webhook travels Cloudflare Tunnel → the container on your Hostinger VPS. Same path for every request, always on the permanent URL.

5

🎶 Queue + hold music + position

The caller waits in a real queue: "You're number N in line, about X minutes" with hold music looping. The app tracks queue depth and wait time live.

6

💻 An agent answers in the browser

Online agents see the waiting caller. The call pops in the console (or "Answer next"). Twilio Voice SDK connects the audio over WebRTC — first to answer wins.

7

🔴 Bridge + dual-channel recording

Caller and agent are bridged. Recording runs record-from-answer-dual — caller on one channel, agent on the other, for clean transcription.

8

🗂️ Auto-write to Zoho

On /voice/recording-status, the app stitches the call legs together (calltracker) and writes a Bridged_Calls record: caller #, agent, queue wait, talk time, outcome, recording URL.

9

📝 Transcript fills itself in

The recording is submitted to Twilio Voice Intelligence. A few minutes later /voice/vi-callback drops the labeled transcript (Agent: / Caller:) into that same record.

↺

📮 No agent available? Voicemail.

If nobody's online or 25s pass with no pickup, the caller leaves a recorded voicemail — which also writes to Zoho and gets transcribed. Missed callers are never lost.

⑤ What Lands in Zoho

The Bridged_Calls module — one record per human-handled call, written automatically.

FieldTypeWhat it holds
Caller NumberPhoneThe number that came through the bridge
Bridge NumberPhoneThe JRH line, (267) 508-7940
Bridge OutcomePicklistAnswered · Voicemail · No-answer
Agent AnsweredTextWhich agent took the call
Queue Wait (sec)NumberHow long the caller waited
Talk Duration (sec)NumberLength of the live conversation
Recording URLURLLink to the dual-channel recording
Recording SIDTextTwilio recording ID
Twilio Call SIDTextCorrelation key for reconciliation
TranscriptMulti-lineAuto-filled, labeled Agent / Caller
Call TimeDate/TimeWhen the call happened
💡 Why a separate module? A bridged call is its own Twilio leg and can't be reliably matched back to the Retell intake record — so instead of corrupting the existing call logs, every human-handled call gets its own clean, trustworthy record.

⑥ Security & Consent

🔒 Password gate

  • Shared team password required before going online
  • Protects the endpoints that mint call credentials — not just the page
  • Stateless signed session token (12h), survives restarts
  • Constant-time check; fails safe

🔑 Secrets

  • All credentials live in env vars on the VPS, never in the repo
  • Twilio, Zoho, Cloudflare, console password isolated per service

⚖️ Consent

  • PA is all-party consent
  • Caller hears a recording notice before bridging
  • Staff give standing consent by employment agreement

🛡️ Isolation

  • No inbound ports open on the VPS (tunnel-only)
  • Runs isolated from other projects on the box
